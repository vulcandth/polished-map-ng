# Find Rust code by an original filename

**Start with the exact old filename.** Every tracked file in pinned upstream
`master/src/` has its own row below, including headers. Click the NG implementation
link, not just the upstream filename. Use your browser's Find for, for example,
`gameboy-screen.cpp`, `config.h`, `image.cpp`, or `resource.h`.

This is a source-navigation index, not a claim of completed behavior parity.
The source inventories are pinned by [upstream.lock.toml](../upstream.lock.toml):
master `8b9bdc2b8aac8c865809516c2123af69c498da0b` (64 files) and
plusplus `27c1f8479107c7495ac0c1818900190a137da6e1` (62 files).
A plusplus link means that filename exists there, not that the contents match.

## Example: gameboy-screen.cpp

[Original drawing code](https://github.com/Rangi42/polished-map/blob/8b9bdc2b8aac8c865809516c2123af69c498da0b/src/gameboy-screen.cpp) lives in
[`crates/gui/src/gameboy_screen.rs`](../crates/gui/src/gameboy_screen.rs): actual
bounds calculation, translucent fill and black/white outlines. It is not a stub
or index facade. [`event_workflows/canvas.rs`](../crates/gui/src/main_window/event_workflows/canvas.rs)
owns whether to draw it; [`geometry::EventCursor::game_boy_screen`](../crates/gui/src/geometry.rs)
is retained as a compatibility entry point to the same bounds implementation.

## Physical filename coverage

This revision changes real source files across GUI, core and project, not just
this index. Count one upstream stem once (replace `-` with `_`), when that exact
`.rs` filename owns implementation under `crates/*/src/`. Headers sharing a stem
with a `.cpp` do not add another stem. This measures discoverability, **not feature
parity or implementation completeness**.

Both branch-specific owners are linked where semantics differ. Existing public
Rust type names and reexports remain intact; these are physical implementation
moves. The whole `main_window/` family retains its split feature ownership,
not a recreated monolithic Main_Window class.

## Why some files have several destinations

Rust models, file I/O and UI belong to different crates. A C++ class that mixed
those responsibilities maps to several implementation files; the links above
show those boundaries directly. Header declarations normally point to the same
Rust implementation as their `.cpp`, rather than an empty matching file.
Toolkit-only classes, build metadata and unsupported legacy theme variants are
identified explicitly, not disguised as implemented Rust equivalents.

Keep meaningful same-name implementation modules where responsibilities match;
use underscores instead of upstream hyphens. Do not introduce empty aliases or a
second source tree merely to reproduce the filename list. The [contributor guide](../CONTRIBUTING.md#finding-the-code)
explains crate ownership, workflows and where tests live. The [architecture](architecture.md#crate-and-module-layout-review)
records why project/platform remain separate from core.
