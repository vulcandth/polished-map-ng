# Compatibility evidence

This is the current coverage/evidence map, not a chronological work log. The
[roadmap](roadmap.md) owns completion and remaining gates. All source comparisons
use [upstream.lock.toml](../upstream.lock.toml); game fixtures stay ignored and
outside distributions. Exact native observations apply to the revisions and
environments stated below, not automatically to every later binary.

Earlier detailed measurements and run narratives remain in
[the pre-cleanup record](https://github.com/vulcandth/polished-map-ng/blob/f79a7dffbbc7a5156bc190e0e4c47590fcbd83cb/docs/compatibility.md).
Current behavior is documented in [usage](usage.md), [menus](menus.md) and
[preferences](preferences.md); intentional differences are in [deviations](deviations.md).

## Initial-release review

The review on `main` preserves the five crate responsibilities and the existing
GUI behavior. [Architecture](architecture.md#crate-and-module-layout-review)
records the boundary decision and extracted editor modules. No snapshot baseline
or aesthetic change accompanies that extraction. The completed
[R1–R4 review](roadmap.md#initial-release-review) was verified at
`1bf228cbb222337a42e347816b4be82944d47447`: Windows formatting, warnings-denied
Clippy, 558 workspace tests (54 environment-dependent tests ignored) and rustdoc
passed, as did all 16 Python tooling tests. All eight
[CI jobs](https://github.com/vulcandth/polished-map-ng/actions/runs/43347427575)
passed, including Windows/Linux/macOS, MSRV, compiled upstream comparisons,
five pinned projects, unchanged visual baselines and dependency/license checks.

Input/persistence inspection reproduced two panics and one incorrect palette write:

- `tile_palettes::tests::commas_inside_comments_do_not_create_palette_rows`
  failed with an out-of-range slice when a comma inside a `tilepal` comment was
  mistaken for another row. Row detection now agrees with the decoder and
  preserves the comment and CRLF bytes while editing the actual palette row.
- `bounded_reads_handle_zero_exact_and_maximum_limits` failed with integer
  overflow for `read_bounded(path, usize::MAX)`. The extra-byte read bound now
  saturates; the test also checks zero, insufficient and exact limits.
- `palette_row_indentation_matches_the_decoder` reproduced a wrong-row write:
  the decoder accepted whitespace that the serializer's row matcher skipped.
  Matching their whitespace rules preserves indentation and updates both real
  rows in order instead of leaving one stale and assigning its color to the next.

The [current archive audit](releases.md#initial-release-archive-audit) covers all four
published unified binary targets and their matching source. Updated packaging
has regressions for selected launcher/version, retained attribution/licenses,
shared notice hashes, target dependency selection, offline documentation links,
source-only links pinned to the exact commit, dirty-checkout rejection and ZIP
executable modes. For the initial R1–R4 review, all five
[packaging jobs](https://github.com/vulcandth/polished-map-ng/actions/runs/43347427189)
passed, building the four targets offline from matching source. Independent
archive inspection verified hashes, architecture, executable modes, source
identity, exact license/notice bytes and local documentation links. The packaged
Windows CLI also inspected a synthetic two-block map successfully; no desktop
GUI testing was performed for this review.

## Code organization and rustdoc

Implementation is organized by current storage semantics and feature ownership;
see the [source map](../CONTRIBUTING.md#where-to-make-a-change) and
[layout decision](architecture.md#crate-and-module-layout-review). Existing
launcher IDs, serialized values, Rust compatibility imports, asset bytes and
test baselines are retained. The extended event catalog is independent of
attribute storage. GUI state/startup/frame handling, event canvas/forms, tile
clipboard/dialogs and CLI parsing/execution/JSON records have distinct owners.

Shared file services/errors are separate from the map lifecycle. Attributed
block persistence has its own feature module, and the GUI uses the shared event
document directly after catalog selection. Typed map/palette adapters retain
their actual format constraints. Private storage and tile-draft names no longer
use the old branch terminology; compatibility names and provenance remain.

Rustdoc checks links, markup and crate landing pages in public and private builds.
Every public library item, field and variant now has documentation, enforced by
`deny(missing_docs)` at all four library roots. Examples exercise map history,
bank addressing, RGB edits and source-preserving event edits, and compile guarded
Save As and read-only discovery workflows. A1 still owns API stabilization.
The review preserves valid-input format semantics and native acceptance status;
the direct PNG helper's malformed-buffer correction is recorded in
[deviations](deviations.md#initial-release-input-robustness-corrections).

Verification on Windows: workspace format/Clippy/tests/doctests, GUI Clippy with
all features, strict public/private rustdoc, production native-adapter features,
documentation links, packaging-tool tests and asset/vendor provenance checks
passed, including 565 tests/doctests with 54 opt-in tests skipped. Function-body
and diff review accounted for moves/private renames, the removed event forwarding
enum, formatting, and shared RGB validation; rendering baselines were unchanged.
The PNG regression verifies invalid data cannot truncate an existing destination
or create a new one, while valid large-image output still decodes exactly.
Fixture/native tests remain opt-in, and no desktop acceptance campaign was run.
The reviewed code at `bce0ec2` also passed all eight

## Discovery and codecs

[Reference tests](../crates/project/tests/reference.rs) pair with the independent
`tools/*_oracle.py` drivers in CI. They cover every 2bpp bitplane pair, bounded
LZ/back-references, ASM/CHR parsing, PNG depths/Adam7/platform alpha behavior,
metadata and asset-path precedence, numeric filename ordering and every
representable Open factor-pair area. [Codec tests](../crates/project/tests/codecs.rs)
and [PNG tests](../crates/project/tests/png_import.rs) cover malformed inputs.

Open sizes use decoded block counts, prefer 10×9 multiples, and honor explicit,
filename and supported metadata context. Shared files require an actual tileset
choice. The GUI can acknowledge oversized prefixes; short files fail, and strict
headless opens reject mismatches. ASM imports preserve source through binary
Save As. Compound names, graphics row padding, output paths and PNG platform
policy remain explicit contracts, covered by
[asset paths](../crates/project/tests/reference/asset_paths.rs),
[discovery](../crates/project/tests/reference/discovery.rs) and
[map opens](../crates/project/tests/map_open.rs).

## Print and fonts

The [source Print differential](../crates/project/tests/reference/printing.rs)
checks native-sized composition, clipping and independent Grid/IDs/Priority/
Events/Warp IDs flags with controlled text masks. [Real-project Print](../crates/project/tests/real_print.rs)
adds actual project data. GUI [worker/input tests](../crates/gui/src/editor/printing/tests.rs)
cover captured live drafts, asynchronous output, overwrite/cancel guards and
native Copy events; [CLI tests](../crates/cli/tests/printing.rs) cover headless use.

Font selection preserves collection indices/variable axes and reports substitutions.
Windows may use Arial Bold instead of synthesized Microsoft Sans Serif Bold;
macOS uses system/fallback UI faces and Menlo/SF Mono/Monaco/Courier roles. CPU
coverage differs from native FLTK hinting. Exact fonts and backend alpha rounding
remain under the aesthetic deferral, not completed Print pixel parity.

## Native profile preference lifecycle

The opt-in [native example](../crates/gui/examples/native_preferences.rs) runs
fixed master and plusplus in separate processes with real eframe windows/storage
and temporary stores. It checks read-only legacy import, NG precedence, shutdown
save, 640×480 → 720×520 normal resize/restart, future-record preservation and
profile isolation. CI runs it on Windows/macOS and isolated Linux Xvfb.

### Addressing and serialization contracts

Attributes use bits 0–2 for palette, bit 3 for bank, bits 5/6 for X/Y flip and
bit 7 for priority. Bit 4 is discarded by the original reader/writer. Offsets and
attributes are separate 16-byte rows. Attribute files may end after fewer whole
rows than offsets; remaining rows are zero. Excess/partial rows fail. Resaving
an edited blockset emits all rows with bit 4 cleared.

| Graphics ordinal | Default bank:offset | Bank 0 first option |
|---|---|---|
| $000–07f | $0:00–7f | $0:00–7f |
| $080–0ff | $1:00–7f | $1:00–7f |
| $100–17f | $1:80–ff | $0:80–ff |
| $180–1ff | $0:80–ff | $1:80–ff |

Changing bank order changes interpretation, not stored bytes. The original
attribute loader enables the 512 option only for a resolved ordinal **greater
than $100**, while graphics count enables it above 256 tiles. Preserve this
threshold in compatibility code; it is not the ordinary >=256 test.

Brush footprints share master's eight modifier patterns, but flip the destination
coordinates across the entire footprint and apply occurrence attributes. At
sheet edges, signed intermediate indices pass through `Tile::bank_offset`;
modulo-512 arithmetic would produce different results. The port bounds public
selected indices while reproducing these internal conversions.

`config.cpp` searches full compound names before the base before the first dot.
Offsets/attributes search `data/tilesets` then `tilesets`. Collisions search
`data/tilesets/*_collision.asm`, `.inc`, then `tilesets/*_collision.asm`, `.bin`;
master's `data/tilesets/*_collision.bin` candidate is absent. Graphics use
`gfx/tilesets` with PNG → 2bpp → 2bpp.lz, roofs use `gfx/tilesets/roofs`.
No palette-map file belongs to a plusplus blockset.
